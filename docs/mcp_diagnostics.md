# MCP 连接诊断与手动测试

## 入口与操作

打开「＋ → 配置工具」：

- 顶部 **MCP 测试**：选择任意已配置服务，包括工具发现失败的服务。
- MCP 服务右侧 **测试**：预选该服务。
- MCP 工具右侧 **测试**：同时预填服务和工具原名。

打开面板只读取配置，不启动服务。点击 **测试连接** 后才启动所选服务，完成协议握手、读取声明的能力、分页获取工具清单并检查参数 Schema。此操作不执行业务工具。

手动调用步骤：

1. 选择服务，可先测试连接获取工具清单和参数说明。
2. 点击「选择工具（可多选）」勾选一个或多个工具，可搜索名称或说明，也可全选筛选结果。没有发现清单时，可直接输入工具原名并点击「加入测试」。不要填写项目为重名工具生成的模型别名。
3. 连接成功、选择工具后，面板自动生成 **表单填写**，直接在对应字段中输入测试值；也可点击 **JSON 编辑** 填写参数对象，例如 `{"url":"https://example.com"}`。未获取 Schema 时可直接使用 JSON 测试。
4. 点击已选工具标签切换当前编辑对象，分别填写参数；每个工具都有独立的表单/JSON 草稿。
5. 点击 **执行测试（实际调用）** 或 **执行 N 项测试（实际调用）**。多项测试按标签序号逐项执行，结果分别展示；点击结果标题可展开查看详细返回。

测试无需模型参与，不生成聊天消息，不改变当前会话的工具选择，也不消耗项目记录的模型调用额度。工具自身调用的外部服务可能收费，或产生文件写入、网页操作等实际效果。

### 工具多选与批量执行

- 工具列表不会按「当前编辑工具原名」自动过滤。通过列表内的独立搜索框搜索，勾选后仍可继续选择其他工具；标签序号即执行顺序，移除后重新勾选会追加到末尾。
- 列表嵌在弹窗中，滚动弹窗/页面、调整窗口、点击外部会收起；滚动列表本身不会收起。Escape 优先关闭工具列表，再次按下才关闭测试面板。
- 启动前先检查所有已选工具草稿的 JSON 格式、基本字段和大小；出现错误会切换到对应工具，并阻止开始这批调用。每项实际执行前，后端仍按服务的原始 Schema 进行完整验证。
- 每项测试单独建立连接、分别计时；超时设置适用于每一项。**批量执行也不共享 MCP 连接状态**，不能作为同一连接上的浏览器导航/截图等工作流测试。
- 默认单项失败后停止，显示剩余未执行数量；勾选「单项失败后继续测试其他工具」可继续后续独立测试。点击「停止等待」会取消当前请求，不再启动剩余工具，已完成的结果仍可查看、导出。
- 批量导出只包含已完成项的脱敏报告，工具清单集中保存一份；成功项详情按需展开，减少多工具结果的页面占用。原始表单、JSON 草稿和可能含请求原文的 HTTP 异常详情不会写入导出文件。

### 表单与 JSON 两种输入方式

- 表单显示参数原名、类型、必填/可选标记和字段说明。字符串使用文本框，数字/整数使用数值框，布尔值和枚举使用下拉框；支持嵌套对象、本地 `$ref` 和可空类型。
- **可选字段默认不发送**，保留服务自身的默认行为。在字段中输入内容会自动勾选「发送此参数」；也可手动取消勾选。勾选后留空的字符串会作为 `""` 发送，数字 `0`、布尔 `false` 都是有效值。可空字段可勾选「设为 null」。
- 数组及复杂的字段 Schema 使用字段内的 JSON 编辑框；复杂根结构、无效或被截断的 Schema 使用完整 JSON 编辑。完整约束仍在后端按服务原始 Schema 验证，表单只辅助输入和检查基本格式。
- 切换到 JSON 会同步已填写的表单参数；尚未填写的必填数字、选项等暂时省略，方便继续在 JSON 中填写。切回表单会解析现有 JSON，保留未列出的字段到「其他参数」，不会将 `false`、`0` 或 `null` 转成字符串。JSON 无法解析、或字段 JSON 格式错误时会提示修正，不会覆盖草稿。
- 测试返回后保留输入；不同服务和工具的草稿分别暂存于页面内存，已选工具草稿不会因切换被淘汰，其他草稿保留在最近使用缓存中（通常最多 32 份）。不会写入浏览器持久存储，刷新页面后需重新填写。
- **填入示例参数**会替换当前草稿，生成必填字段的结构示例，不执行工具，也不保证满足所有约束。Schema 的默认值和示例在诊断报告中经过隐藏，不会将 `[REDACTED]` 当成默认参数自动发送。

表单采用紧凑布局，宽窗口为双列，窄窗口为单列，嵌套对象横跨整行；较长的工具说明默认折叠。参数较多时在弹窗内滚动即可。工具参数原名与结构不会因为使用表单而改变，两种方式最终调用相同的诊断接口。

## 测试范围

### 现有浏览器扩展连接

聊天的「配置工具」中仅有一个 Browser 服务和一份工具清单，提供两套功能预设及全选。诊断面板也只列一个 Browser，通过「连接配置（profile）」选择 isolated / extension。所选目标放在 HTTP 请求顶层 mcp_profile，不混入微软工具的原始 JSON 参数；表单和 JSON 两种输入都可使用。组内及单工具测试不改变聊天工具勾选。

扩展服务的握手、工具清单发现不需要先选业务页面；「测试连接」成功不表示网页已连接。首次实际调用需要在运行后端的电脑上，通过目标 Chrome / Edge 的 Playwright Extension 授权并选择标签页，可先将测试超时设为 120 秒。测试结束会断开本次连接，聊天使用另一条常驻连接，可能需要再次授权。依赖连续页面状态的操作请在聊天中验证，详见 [浏览器工具说明](browser_tools.md)。

### 通用边界

- 目前与项目 MCP 客户端一致，只支持 `setting/mcp_servers.json` 的 `servers` 中配置的 **stdio** 服务。不接受请求传入任意启动命令；内置工具不属于此面板。
- 每次连接测试或工具测试都使用**独立的新连接**，结束后关闭，不复用聊天中的常驻 MCP 会话。因此不能用连续点击测试来验证依赖同一连接状态的工作流。浏览器导航后再截图等操作，应在正常聊天的常驻服务会话中验证。
- 新连接不是业务隔离：服务仍继承正常配置的环境和访问权限；外部文件、浏览器资料、数据库等状态可能共享。
- 连接成功仅证明握手和工具发现正常，声明了某项能力不等于对应功能已经验证。只有明确点击实际调用后，才验证该工具和该组参数的执行结果；不自动遍历调用所有工具。
- 超时可设 **1–300 秒**，默认 30 秒，涵盖启动、握手、工具清单、参数验证、调用与连接关闭；底层进程清理可能增加少量耗时。最多同时进行 3 个测试，超出返回繁忙。
- **停止等待**、关闭面板或请求断开会取消后端测试并关闭连接，释放测试名额。已经发生的外部操作无法撤回，服务派生的独立进程也可能继续运行。
- 参数必须是 JSON 对象，序列化后不超过 64KB。支持本地 `$ref`；不下载远程 Schema。清单最多检查 2000 项，面板最多展示 200 项，仍可手动输入其他完整工具名。

## 结果与错误

结果展示成功阶段、协议版本、工具数量、耗时、工具返回和完整报告；空结果可正常成功。工具返回 `isError=true` 会按执行失败展示，同时保留业务错误正文。

| 分类 | 常见原因 |
| --- | --- |
| 配置错误 / 启动命令不存在 | JSON 格式、command/args/env、依赖或 PATH 有误 |
| 不支持的连接方式 | 配置为 HTTP 等当前客户端未支持的传输 |
| 权限或认证失败 | 文件执行权限、服务返回认证/授权错误 |
| 连接中断 / 协议交互失败 | 服务退出、向标准输出混入日志、JSON-RPC 不兼容、分页异常 |
| 测试超时 | 冷启动或业务调用超过设置时间 |
| 工具不存在 / 参数说明异常 / 参数不符合要求 | 原名错误、Schema 无效或远程引用、必填字段和类型不符 |
| 工具执行失败 | 服务抛出调用错误或返回 `isError` |

分类按异常类型和部分认证/连接错误特征判断，辅助排查；第三方服务任意业务错误仍需结合正文和 stderr 判断。

## 脱敏报告

可复制或下载 JSON 报告。报告包括阶段、错误、能力声明、工具参数说明、已脱敏调用参数及返回、末尾 stderr；不会包含启动命令和完整环境变量。后端统一处理配置和环境中的常见密钥、输入的敏感字段、Bearer、带认证信息的 URL、常见本地路径。Schema 属性名保留以便填写参数，但默认值和示例被隐藏。

报告限制嵌套层数、条目数和正文长度，图片/音频和资源 blob 二进制内容不写入；工具返回内容约限 128K 字符，结构化结果单独限量，stderr 只取末尾约 12KB。报告不是完整业务输出。

脱敏无法识别所有业务隐私、未标注的凭据和全部路径形式。**对外分享前仍请检查正文。** 编辑框保留手动输入以便修正，但复制和下载只使用后端返回的报告，不额外打包编辑框原文。

## HTTP 接口

`GET /tools/diagnostics` 返回配置的服务 ID、传输方式、配置状态与 `persistent`；识别到 Playwright 时还附带 `browser_mode`、`browser_channel`、`connection_label`、`connection_hint`。配置了 profiles 时还包含 mcp_profiles/default_profile/locked_profile。这些是公开提示，不包含启动命令、端点、token 或原始环境变量；读取不连接 MCP。诊断报告可包含相同的 `connection` 提示字段。

`POST /tools/diagnostics` 示例：

```json
{
  "server_id": "WebServer",
  "action": "call",
  "tool_name": "fetch_url",
  "arguments": {"url": "https://example.com"},
  "timeout_seconds": 30
}
```

任何配置了 profiles 的 MCP 均可在 HTTP 顶层传 mcp_profile；例如 Browser 的 extension / isolated，省略时使用默认或固定连接。arguments 使用所选连接的原始 Schema，不套模型调用封装；诊断报告记录实际 profile。各连接的工具选择与草稿分别保存。详见 [通用 profiles](mcp_profiles.md)。

连接测试使用 `action: "connect"`，无需填写工具和参数。诊断完成的请求返回 HTTP 200，业务成功由 `ok` 判断；失败时有 `error.code / phase / message`。不存在的服务返回 404，请求参数或配置读取错误返回 422；客户端取消等待时后端取消任务。

多选测试由前端按顺序发送多个 `action: "call"` 请求。下载报告中的 `action: "batch_call"` 是前端汇总格式，不是新增的 HTTP 请求 action；包含 `requested_count`、`completed_count`、集中保存的 `tools` 及各项 `reports`，必要时标记 `cancelled` 或 `stopped_on_error`。

首次引入诊断接口后需要重启后端并刷新前端。本次通用 profiles 改动也需要重启后端。已有运行任务请先完成或停止后再重启后端。
