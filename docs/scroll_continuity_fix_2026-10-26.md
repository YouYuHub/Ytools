# 长任务滚动连续性修复（2026-10-26）

## 结论先行

存在问题，已修复。长会话（尤其工具密集型任务后）上下滚动时，每约 600px
出现一次滚动条 3 倍跳动（滚轮 200px → 滚动 650px），并伴随窗口边缘约 1 帧的
空白闪现；展开的思考/工具块一切换窗口就全部收起。体感即“一下跳过一些渲染块”。

流式链路本身无性能问题：300 条高速增量 + 同步滚轮下帧率稳定 60fps、零长任务；
`processGroups.sync` 单次 P95 仅 0.5ms；内容锚点补偿逻辑正确（逐帧跟踪首可见
记录无跳号）。问题集中在历史窗口的高度估算与换窗时机。

## 根因

1. **高度估算系统性偏大约 1.3–2.5 倍**（`H5/js/history_scroll_model.js`）。
   实测（1300px 视口）：用户气泡 chrome 约 86px（估 100）、助手正文 chrome
   约 38px（估 64）、行高约 22px（估 26）、用量行 21px（估 52）、折叠摘要
   条 32px（估 58）。窗口按像素规划（视口中心上下各 1.5/2.5 屏），估算偏大
   导致真实覆盖只有约一半，滚动约 600px 就撞到窗口边缘触发重建（应为
   1300px+）；每次重建用实测修正占位，滚动条一次修正约 450px。
2. **换窗无预取**（`H5/js/app/history_scroll.js` 的 `covered` 判定）。
   旧逻辑等到视口边缘真正露出空白占位才重建，空白闪现 + 滚动条跳动同时发生。
3. **思考/工具块展开态不持久**（`H5/js/app/messages.js`）。
   窗口重建销毁 DOM 后，`buildThinkBlock`/`buildToolBlock` 永远以折叠态重建；
   只有过程分组的展开选择被记住。回看长任务时展开的内容一滚动就全收起。
   （往返验证：修复前展开 1 工具+1 思考 → 滚走滚回 → 0 展开；修复后 1/1 恢复。）

## 修复

- `history_scroll_model.js`：用户 chrome 100→72、助手 chrome 64→28、行高
  26→22、用量行 52→24。校准后典型记录估算误差收敛到 ±25% 以内（偏向轻微
  高估，保证覆盖）。`tool/think/compaction` 的 112 回退值不动（有分组模块
  时走不到该分支）。
- `process_groups.js`：折叠首条估高 58→36（实测摘要条 32px）。
- `history_scroll.js`：`covered` 增加预取边距（400px 与半屏取小，首尾无更多
  内容的一侧不预取防空转）。视口接近边缘即提前换窗，此时视口仍被完全覆盖，
  重建+锚点补偿用户无感知；拖拽冻结路径不受影响（先按索引命中直接返回）。
- `messages.js`：思考/工具块展开态持久化到 `App.__stageOpenChoices`
  （Map，上限 800，FIFO 淘汰）。工具键优先全局唯一的
  `tool:<agent>:<tool_call_id>`（子任务按 agent 隔离，旧记录回退
  会话+轮次+下标键）；思考键为 `think:<会话>:<轮次>:<事件>`（与分组历史键
  同口径）。仅用户显式点按/双击记录，流式与搜索程序展开不算；重建时恢复，
  延迟 diff 视图随展开即时生成（复用既有 `ensureDiffView` 入口）。

## 验证（均为本机实测，合成数据）

- 同一 500 条历史 + 40 工具长尾、1300×900、-200px 滚轮 ×120 步：
  修复前跳动 20 次（-644 ~ -722px/步）、总高度虚高 70180px；
  修复后跳动 **0 次**、总高度 52548px（与真实一致）。
- 全量可见性往返：500/500 记录均进入过视口，无遗漏。
- 平滑滚动 + 连续滚轮逐帧跟踪：首可见记录无跳号（>6/帧为 0）。
- 折叠/展开工具密集历史往返：跳动 0；展开态往返恢复。
- 前端全量：856 passed（含新增 `test_h5/stage_open_choices.test.js` 3 项）。
- `test_frontend_asset_versions.py`：5 passed（已跑 `version_assets.py` 更新哈希）。
- 复现脚本保留在 `tmp/repro_*.cjs`（`repro_sweep`/`repro_visibility`/
  `repro_smooth`/`repro_expanded`/`repro_roundtrip`/`repro_jank` 等）。
