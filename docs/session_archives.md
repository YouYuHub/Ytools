# 历史会话归档（已实现）

## 使用方式

1. 在侧栏会话的「…」菜单选择「归档」；当前已保存会话也可在右上角会话操作菜单中归档。
2. 侧栏底部原来的「主题」按钮已改为「设置」。点击后上拉菜单提供「归档会话」「主题」「聊天设置」。侧栏收起时点击底部头像打开同一菜单，不会展开侧栏。
3. 在「设置 → 归档会话」窗口浏览归档标题。支持按标题或会话 ID 筛选，每页 50 条，可加载更多。
4. 点击归档标题打开原会话并继续聊天；输入区上方显示「已归档 · 可继续聊天」和「取消归档」。继续聊天不会自动取消归档。
5. 归档窗口可取消归档或永久删除；删除需再次确认，失败保留记录以便重试。正在前台生成的会话需先停止再删除，其他运行任务沿用现有删除接口的停止逻辑。
6. 常规搜索默认只查未归档会话；需要时可切换为「已归档」或「全部会话」，归档结果标注「已归档」。归档窗口的「搜索归档内容」直接打开仅归档全文搜索，再次从普通入口打开则恢复未归档范围。
7. 输入 `/归档` 可打开归档管理窗口，`/主题` 仍直接打开主题选择。

## 行为约定

| 情况 | 行为 |
| --- | --- |
| 归档 | 从侧栏「最近」及分组成员列表中隐藏；当前聊天可以保持打开 |
| 归档时正在生成 | 归档不停止生成，也不移动文件；原任务、刷新恢复和工具结果继续使用原会话 ID |
| 继续聊天/修改历史/生成标题 | 保持归档，不因本地最近访问缓存或发送消息重新出现在侧栏 |
| 取消归档 | 恢复到普通列表，保留原分组；按原有最近活动时间排序 |
| 删除归档会话 | 永久删除会话及既有接口负责清理的附件、原生协议记录等，并移除归档标记 |
| 删除分组 | 沿用现有解除归属规则；不会删除归档会话或取消归档 |
| 分享/导出 | 聊天及附件仍可按原功能导出。归档是本机整理状态，不随分享包传给接收方 |
| 导入 | 新 ID 的导入会话默认未归档；覆盖已有归档会话时保留本地整理状态 |
| 重启/刷新 | 从后端归档状态文件恢复；不是只存在浏览器缓存中的隐藏标记 |
| 其他客户端更改归档 | 重新加载会话列表或刷新页面后同步，不新增轮询任务 |

归档不清除摘要、工具结果、上下文状态、模型选择、预算、权限或附件，不改变三个模型 API 的历史处理及继续聊天逻辑。归档不提供加密、访问隔离或释放磁盘空间。

## 实现与存储

归档标记按账户保存在 `history_files/users/<user_id>/session_archives.json`：

```json
{
  "version": 1,
  "sessions": {
    "会话ID": {"archived_at": "2026-10-21T04:00:00+00:00"}
  }
}
```

仅保存已归档会话；取消归档删除对应条目。时间以 UTC ISO 格式持久化，重复归档保留首次时间。

选择独立的小状态文件，是为了避免归档一个大型会话时重写整个 JSONL，也避免 worker 在写轮次、摘要或用量时覆盖整理状态。原 JSONL、附件目录、Messages/Responses 原生记录位置均保持不变。

- 归档写入通过跨进程文件锁串行处理，使用临时文件、flush/fsync 和原子替换。
- 变更前检查会话真实存在，不为无效 ID 创建空历史。
- 删除会话在删除 JSONL 后清除归档标记，与归档操作共享状态文件锁，避免同 ID 重建时遗留隐藏状态。
- 状态文件缺失表示无归档；格式错误会返回错误并保留原文件，不静默覆盖或把全部归档当作普通会话展示。
- 归档列表仅读取归档会话的元数据首行，不初始化 ChatMemoryManager，也不加载全量正文。
- 侧栏仅请求未归档摘要，后端先根据文件名和归档状态筛选，再打开对应文件首行。同一响应附带轻量 `archived_ids`，用于清理本地最近访问缓存、同步其他客户端的归档状态，不再读取和传输全部归档标题等元数据。指定会话 ID 打开时仍可查询全部范围。
- 搜索先取得归档快照，只对所选范围内的 JSONL 检查指纹、读取变更内容。范围外的缓存保留，但不更新其指纹；之后切换范围或取消归档时自动补齐，不需重新索引未变更的正文。删除检测仍检查完整文件名列表，避免残留命中。
- SQL 先选出范围内的会话，再通过文件索引访问对应文档；不只在最终结果阶段排除归档。计数和分页使用相同范围，归档状态纳入 revision，范围变化会使旧分页失效。索引期间归档状态变化则返回 409，要求重新搜索，避免提供不完整快照。
- JSONL、附件和运行中任务均不搬迁。归档可读可写、可取消、可继续聊天，不需要目录迁移；它节省常规列表/搜索的读取与匹配开销，不以删除聊天数据或缩小现有缓存文件为目标。

完整备份请保留整个 `history_files`，包括各账户目录下的 `session_archives.json`。该文件与可重建的 `history_search_<user_id>.sqlite3` 搜索缓存作用不同，不应将归档状态当缓存清理。若状态损坏，先备份再恢复此文件；历史 JSONL 内容不受归档文件损坏影响。

## 接口

### PUT /chat_history/archive

```json
{"session_id":"会话ID","archived":true}
```

返回：

```json
{"session_id":"会话ID","archived":true,"archived_at":"2026-10-21T04:00:00+00:00"}
```

`archived` 必须为 JSON 布尔值；false 取消归档并返回 archived_at=null。不存在的会话为 404，无效请求为 422，状态读取/写入失败为 503。重复操作幂等。

### GET /chat_history/archives

参数：q（标题/ID，最多 200 字符）、limit（1–100，默认 50）、offset（默认 0）。

返回：`{sessions, total, archived_count, offset, next_offset}`。sessions 为轻量摘要，包含 id、filename、title、updated_at、created_at、group_id、archived 和 archived_at。total 为本次筛选计数，archived_count 为所有存在的归档会话数量。排序按归档时间倒序。

### 既有接口扩展

- `GET /chat_history/summaries`、`GET /chat_history/sessions`：新增 archive_scope=active/archived/all，默认 active。指定 ID 打开归档会话时需使用 all；前端已接入。
- `GET /chat_history/summaries?with_archive_state=true`：返回 `{sessions, archived_ids}`，两个字段基于同一归档状态快照；不传此参数仍返回原有摘要数组。
- `GET /chat_history/meta`：额外返回 archived、archived_at，覆盖展示状态，不把这些字段写入 JSONL。
- `GET /chat_history/search`：archive_scope=active/archived/all，默认 active；每条结果额外包含 archived。额外返回 checked_files（范围内检查数）、indexed_files（本次重建数）、excluded_files（范围外跳过数），便于验证读取范围。
- `DELETE /chat_history/delete_file`：沿用原删除流程并清理归档标记。

代码含后端接口及前端资源变更。正在运行的任务完成或停止后重启后端，再刷新页面使用；不要求迁移既有历史。
