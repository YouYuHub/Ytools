# 分享与加载账号隔离检查

检查日期：2026-10-25。范围：登录账号切换、会话列表与检索、历史和附件读取、ZIP/JSONL 分享预检与导入、冲突选择、权限与分组还原。

## 结论

会话以不可变账号 ID 登记归属，登录用户名或显示名变化不会转移数据。服务器加载按当前身份检查，前端缓存也按账号区分。分享是独立副本，不是公开链接或共享编辑；管理员也不能直接读取其他账号的会话。

本机只读检查了 149 个会话登记：全部使用账号独立目录，未发现导入路径错位或正常会话文件缺失。本次未迁移、重写真实聊天内容。多账号验证使用临时服务和临时账号，不操作真实登录凭证或验证器。

## 已修复的问题

| 问题 | 修复与验证要点 |
|---|---|
| 新建 JSONL 导入成功但重新打开找不到 | 先登记归属，再按最终 ID 解析账号目录；新接口和旧上传入口都可立即读取 |
| 外部 ID 与其他账号占用、预登记 ID 冲突 | 预检只把自己的历史作为覆盖冲突；外部占用 ID 另存，禁止覆盖或接管 |
| 旧格式 `upload_id` 可能指向他人附件 | 裸 JSONL 不接受外部附件目录；ZIP 使用新暂存目录；各账户附件目录物理隔离，不存在跨账号目录共享 |
| Windows 大小写与 Unicode ID 导致路径、缓存不一致 | 授权后统一使用登记 ID；Windows 会话 ID 大小写折叠，Linux 保持大小写区分，仅大小写不同的 ID 分别分享 |
| 并发导入争用目标、旧缓存返回过期内容 | 同来源目标分配与提交加锁，成功后失效聊天及文件管理缓存，晚到的文件列表响应不能覆盖新状态 |
| 无效记录覆盖、存储额度漏检 | 纯损坏 JSONL/ZIP 拒绝提交；历史和附件均检查额度，原历史及附件保留 |
| 分享可能带出嵌套模型认证配置 | 清除模型配置各协议层的请求头及认证字段，保留正常参数；工具和正文中的业务内容仍由分享者核对 |
| 前端实际上传缺 CSRF，账号切换后旧页仍可能请求新账号数据 | 统一上传鉴权、进度及取消；只对明确 CSRF 拒绝重试一次；预期账号不一致先拒绝，再处理正文 |
| 多文件导入弹窗互相替换、尚未保存就统计成功 | 逐份等待确认与提交；区分保存、预览、跳过、失败；提交中防重复，刷新失败明确说明已保存 |
| 主区为空时无法分享侧栏已有会话 | 只校验实际分享目标，已有历史可从侧栏直接下载 |
| 导出超大或附件读取失败时可能生成不可用分享包 | 导出限制大小，预留清单开销；读取失败明确报错 |

## 权限边界与保存范围

- 普通成员可读取、下载自己的会话；服务器持久化导入仍要求管理员或明确授权的可信操作员。成员的本地预览没有保存到服务器。
- 会话权限快照只影响接收端成功导入的会话，不转移账号角色、执行授权、任务、审批或身份库。分组按接收账号范围内的名称映射。
- 分享包含已经落盘的历史及附件；正在生成且尚未提交的一轮需结束后重新分享。各账号仍共享实例磁盘和运行资源，目录隔离不等于执行环境隔离。
- 分享内容中的正文、思考、工具参数及结果属于业务数据，仍会被导出；本次不执行任意正文密钥扫描。
