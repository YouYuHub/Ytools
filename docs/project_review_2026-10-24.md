# 项目复查与修复记录（2026-10-24）

本轮检查账号边界、页面初始化、跨窗口同步、请求校验和限流，并回归文件/终端、文件历史、搜索发现、流式连接与压缩事件。验证使用临时账号和临时数据，不请求真实模型，不修改现有用户密码、验证器或聊天正文。这是有范围的源码检查与回归，不代表已证明整个项目没有缺陷。

## 已复现并修复

| 问题 | 原来的表现 | 本轮处理 |
| --- | --- | --- |
| 文件编辑器未接入账号保护 | `/ui/editor.html` 被白名单拒绝；页面没有账号初始化脚本，放开路径后仍缺少 CSRF 和账号缓存隔离 | 编辑器作为受保护页面提供，注入本人账号上下文，在主题/API 之前加载身份脚本；匿名跳转登录，初始密码未修改时跳转账号页；文件 API 继续检查会话归属 |
| 文件变更的多窗口同步失配 | 缓存键增加账号前缀后，`storage` 监听仍比较旧键，备用刷新失效；广播通道也没有区分账号 | 存储事件和广播通道使用同一账号命名空间；忽略其他账号、其他存储区域及消费标记的删除事件 |
| 编辑器资源没有版本号 | 主页面升级后，独立编辑器仍可能使用缓存中的旧脚本/CSS | 资源版本脚本覆盖编辑器，保留脚本执行顺序；增加登录、账号及编辑页资源哈希检查 |
| 异常输入引发 500 | 非 ASCII CSRF、损坏的 Host/Referer、超长 Content-Length、深层 JSON，以及 NaN/Infinity/溢出浮点数会进入未处理异常或错误序列化异常 | 分别返回 400/403/413/422；保持来源、Cookie、CSRF、会话归属要求；JSON 结构最多 128 层，正常大文本不按字符扫描或误当嵌套结构 |
| 普通写请求的重复持久化 | 请求次数和写入次数分别开启事务、提交一次 | 按原顺序在一个事务内检查/记账，减少一次提交与线程调度；阈值不变，后面的额度不足时，前面已消费的额度仍记账 |

## 本机性能测量

使用临时 SQLite 库，交替执行 5 轮，每轮 120 次普通写请求的两项限流记账，记录每请求中位耗时：分别提交约 **22.214ms**，合并提交约 **10.963ms**。这是限流持久化的微基准，不等于 API、数据库整体或模型首帧耗时下降相同比例。

另用含 500 条文本消息、约 1.04MB 的临时 JSON，分别运行 30 次：普通解析中位约 **1.410ms**，增加深度和有限数值检查后约 **1.638ms**。合法大段文本无需逐字符检查嵌套，也不复制整份解析树；实际开销随机器和输入变化。

## 后续建议，按顺序推进

1. **补页面端到端回归。** 首先覆盖两账号切换、打开编辑器并保存、MFA/近期验证导致的 Cookie 轮换、长流连接与刷新恢复。此次编辑器问题暴露的是页面与后端边界的集成缺口，单独组件测试通过仍可能漏掉入口失效。
2. **统一页面登记。** 受保护页名单、账号注入和资源版本处理目前仍在不同模块维护。下一步可用同一页面清单驱动，并让新增 HTML 页面必须通过身份与缓存检查，减少遗漏。
3. **完善只读体验。** 普通成员的文件写入会被服务端拒绝，编辑器仍可进一步按 `executionAllowed` 明确禁用保存/回退等控件，避免填完内容才收到拒绝。服务端权限检查继续保留。
4. **按职责逐步拆模块。** 本轮统计 `messages.js` 约 5386 行、`builtin_tools.py` 4870 行、`chat_memory.py` 4697 行。优先分离消息渲染/过程分组/导航计算，以及工具参数定义/执行适配；每次拆分使用现有回归保护行为，避免一次性重写。
5. **建立持续验证与部署验收。** 固定 Windows/Linux 测试入口，重点保留真实终端交互、文件换行/编码、权限与 SSE 场景；按实际支持范围增加 macOS。Linux 云端还需验收 HTTPS 代理、SSE、备份恢复和受限服务账号。如果未来允许不可信用户使用终端，应先建设独立执行器；现有可信操作者共享宿主权限的约束不变。
