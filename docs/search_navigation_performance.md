# 搜索跳转后的侧边栏拖动卡顿

> 2026-10-22 更新：聊天区现在使用完整历史高度索引和可视窗口渲染。下文 2026-10-21 的“拖动期间不换段、松手再定位首尾”方案已被替换；当前行为以文末说明为准。

## 原因

正常打开会话时先显示末尾一段。旧的搜索跳转逻辑也先打开末尾，然后每次向前补 160 条，直到命中记录进入 DOM；同时后台回填会继续补全其余历史。因此搜索较早的消息后，页面会挂载大量与当前阅读位置无关的内容。

滚动处理还会遍历全部代码块，测量后代元素的矩形。这些测量会强制浏览器布局原本由 `content-visibility:auto` 跳过的消息。随后拖动侧边栏改变正文宽度，大量内容重新排版，出现明显卡顿。指针事件中的同步布局读取和附件网格重算进一步增加了开销。

这解释了为什么正常会话拖动尚可，而搜索跳转后明显变慢。

## 修改

- 搜索把命中的轮次、事件位置传入 `openSession`，直接渲染目标附近约 120 条记录。引用、问题导航也可以直接切换到目标窗口。
- 停止自动补齐整段历史；通过边缘加载条按需加载，每批约 80 条，边界保留工具调用与结果的配对。滚动到端点的定位行为见文末修正。
- 问题导航从完整记录建立，未挂载的提问仍可选择；使用记录下标区分同轮内多条 user 消息。
- 返回底部时恢复历史尾部窗口，并恢复当前会话的实时消息节点。历史用户消息构建时不再逐条触发自动贴底。
- 分页观察器和加载定时器在切换会话、切换窗口时清理，增量渲染保留分页状态。
- 侧边栏移动事件合并到每个动画帧，拖动起点的坐标和阈值只测量一次；松手保存最后位置，取消则恢复原状态。
- 拖动期间暂停附件网格、代码复制按钮的重复测量，结束后刷新；滚动时仅测量可见消息中的代码块，读写分离。
- ask_user 提交时使用完整历史判断后续回答，避免尚未挂载的后续消息影响确认流程。

主要代码：`H5/js/app/history_search.js`、`sessions.js`、`messages.js`、`core.js`、`builtin.js`。

## 2026-10-21：聊天区原生滚动条拖动

右侧滑块不跟手、按住鼠标停在顶底时页面抖动，来自几种逻辑叠加：

- `content-visibility:auto` 用估算高度占位，拖动途中真实布局不断改变 `scrollHeight`，滑块与鼠标的比例关系随之变化。
- 顶底的历史加载入口由观察器触发，追加内容及顶部锚点补偿会在原生拖动尚未结束时移动页面。
- 流式自动贴底、输入区底部留白修正及尚未完成的定位校正也可能写入滚动位置。

处理方式：保留浏览器原生滚动条及鼠标拖动。鼠标移入滚动条时预先测准已挂载内容，避免按下时改变原生滑块的命中位置；按下后保持滑块比例位置，并临时锁定内容外层高度、关闭滚动锚定和滚动动画。未加载历史仍不挂载。拖动中暂停边缘加载、自动贴底和搜索的延迟定位。流式内容继续接收，新增高度在松手后恢复。

松手后恢复懒渲染。在顶端释放时定位会话第一段，在底端释放时恢复真正的历史尾部和当前实时消息；均直接建立目标窗口，避免将中间历史全部挂载。端点定位不再调用追加历史的旧锚点补偿。在中间松手则保持阅读位置，拖动途中经过的旧方向不会排队执行。只有到底部时才恢复跟随。窗口失焦、隐藏、调整大小或指针取消会释放锁并保持暂停，避免残留拖动态。正文点击、代码块自身滚动条和触摸操作不触发此锁定。

### 松手与滚轮到端点后的回跳修正

上轮验证遗漏了松手之后的分页落点。复现中，顶部释放时 `scrollTop` 原为 0，自动追加 80 条历史后，旧锚点补偿将它推到约 36,739px；底部也会因追加后续内容离开端点。这同样影响滚轮到达边缘。

现在采用一致的端点语义：滚动条释放、滚轮或翻页按键到达两端后，定位会话真正的开头/结尾，只渲染首尾附近的窗口。顶部加载条与底部加载条仍可点击，每次连续展开约 80 条，并保留当前阅读锚点；问题导航与搜索仍可直接打开中间窗口。

观察器不再在距离端点 120px 时提前插入历史。滚轮/按键必须具有最近的用户输入意图才会触发端点导航；搜索、引用等程序定位不会被改成跳转整个会话首尾。代码块内部能够消费的滚轮、缩放手势及编辑控件输入不触发外层端点导航。已经停在当前窗口端点时，也直接响应继续滚轮，避免浏览器不再产生 `scroll` 事件而无法跳转。

验证：

- `npm test --prefix H5`：**619 项通过**，覆盖拖动识别、释放清理、暂停贴底、流式高度恢复、首尾定位、程序定位隔离与内部代码块滚轮。
- `node H5/test_browser/native_scrollbar.cjs`：使用项目固定版本的 Playwright、真实系统滚动条和 600 条合成历史，离线替代接口，不读写真实会话。
- 本机 Chromium、1300×900 下，五个中间落点双向拖动，滑块与鼠标偏差最大 **1px**；顶底按住不动时连续 18 帧位置和高度保持一致。补充验证普通打开/搜索打开 × 顶部/底部四组释放落点，均停留真实首尾；连续滚轮和已经夹在端点的再次滚轮也能正确定位。

## 2026-10-22：按住滑块时就显示对应的完整历史位置

### 本次问题的原因

上一轮只固定了当前分段的高度，滑块实际代表约 120 条已加载记录，完整会话的其它记录不在滚动范围中。到达滑块端点时，页面仍是分段首尾；只有松手才换成真正的会话首尾。这与滑块位置应代表整段会话的直觉不符，仅在释放时补跳不能解决问题。

### 当前实现

1. **完整历史共享滚动坐标。** `H5/js/history_scroll_model.js` 为全部记录建立累计高度索引。未挂载记录按文字、附件及记录类型估高；实际挂载后使用真实高度更新。工具结果与隐藏审批不重复估高，也不将图片、视频的二进制内容当作正文计算高度。
2. **滚动过程中切换窗口。** `H5/js/app/history_scroll.js` 根据滑块当前位置，通过二分查找定位记录及记录内部的比例，再调用消息模块构建附近窗口。两端未挂载内容由留白表示；拖动到顶部/底部时，鼠标仍按住也已显示真正的首条/末条消息。滚轮、搜索及问题导航使用同一坐标和窗口入口。
3. **按住时范围固定、正文同步。** 原生滚动条仍由浏览器控制。手势开始时冻结完整滚动范围及高度索引快照；途中仅移动实际窗口的绘制位置，不改变滑块所用的外层高度和首尾留白，避免布局更新干扰拖动。滚动事件按动画帧合并。
4. **松手保持可见文字。** 解锁前保存真实可见节点及其屏幕坐标，解锁后更新高度估计并恢复该节点的位置；不再在 mouseup 另做一次首尾导航。在真实顶部/底部释放则继续停在对应端点。
5. **保留交互状态。** 运行中消息始终保留为聊天区的直接子节点；查看较早历史时暂时隐藏，流式更新继续，返回尾部仍可看到完成结果。历史编辑框离屏时保留原 DOM、草稿和本地附件，返回时复用。切换会话后清理观察器、调度与暂存节点。

通常窗口约 120 条记录，拖动时约 48 条并按视口高度扩展预读区域；配对边界可适当扩展。不会为了得到滑块范围而构建整段 Markdown/工具 DOM。未查看内容的高度仍是估值，字体、宽度或展开状态变化后会修正范围；首尾位置及松手前后的可见文字保持一致。

## 2026-10-22：新提问及时进入导航

长会话窗口重建先根据历史快照刷新导航，随后再挂回尚未纳入快照的实时轮次；旧顺序没有再次刷新导航。任务完成后活动流已清理，更容易出现“消息还在，导航入口却少了最后几条”。另外，按后端 round 去重会忽略同轮内的用户引导；轮次确认前用重复文字寻找实时气泡，还可能误收养历史中的另一条“继续”。

当前处理：补回实时用户节点后同步导航；`round_started` 确认轮次后同步一次；优先保留本次气泡的对象身份。历史/实时去重使用记录位置、事件及内容匹配，同一轮的额外用户消息保留；编辑替换显式标记被替换的轮次，更新原入口。导航面板重建保留原阅读位置，原本停在面板末尾时跟随新增项。

验证：前端全量 **639 项通过**；`ask_answer_stream.cjs` 覆盖运行中及完成后的最新提问、25 次工具调用、历史窗口切换、连续续答及显式插入，确认导航不丢最后几条；`native_scrollbar.cjs` 的真实滑块、首尾、搜索、提问定位和实时输出回归通过，浏览器均无错误。测试只用合成历史与模拟接口。
