# 历史按需加载

2026-10-25：新增只读分页，不改变 JSONL、模型上下文、分享或备份格式。

## 页面行为

- 默认先取最近 20 轮。上滚到尚未加载的区间时继续取页，也可点击“加载第 … 轮历史”。加载期间保留当前阅读锚点。
- 问题导航先获取轻量完整索引，预览文字最多 240 字符；点击目标问题或搜索结果时获取对应轮次，完整问题和正文不截断。已浏览轮次在页面内复用，切换会话后清理。
- 超过 32 KiB 的普通工具结果和差异先提供摘要；打开工具详情才读取原始结果，成功后复用。`ask_user` 与子任务聚合继续沿用原展示流程。
- 分页保持完整轮次；原始数据预算为每页约 2 MiB，单个超大轮次允许超出预算，避免截断正文或思考。大 JSONL 页面继续由 Worker 解析，Worker 及其依赖也使用内容哈希版本。
- 对存在运行中／挂起检查点的会话，保留原完整历史及检查点合并路径，避免遗漏审批、插入或恢复轨迹。旧版后端未声明能力时也保留原加载方式。

## 接口

| 接口 | 参数 | 行为 |
|---|---|---|
| `GET /chat_history/page` | `session_id`；`limit=1..100`，默认 20；可选 `before` 或 `around`；可选 `revision`、`include_questions` | 完整轮次 JSONL、绝对轮次偏移、总轮数、快照版本；首次包含问题索引 |
| `GET /chat_history/event` | `session_id`、`round_no`、`event_index`、64 位 `revision` | 原快照的一条工具结果，供展开详情 |
| `GET /chat_history/file` | `session_id` | 原有完整历史下载与检查点合并，继续保留 |

`before` 是排他的轮次上界，不能与 `around` 同用。页面只使用服务端确认的绝对轮次；不因分页重新从 1 编号。

两个新接口先检查账号归属，未知或其他账号会话返回 404，不创建会话或目录；拒绝通过符号链接／目录联接访问。详情不接受任意文件路径，也不能用于读取模型私有回放事件。

## 快照与缓存

内存缓存最多保留 8 个会话、约 16 MiB 的偏移及问题索引，不缓存全部原始轨迹，缓存键包含账号 ID 实现账户隔离。首次索引需流式扫描一次源文件；文件身份、大小和修改时间改变后重建偏移。每次读取前后检查快照，不能混读正在替换的文件。

逻辑版本覆盖轮次、独立压缩事件与用量。只修改标题或诊断元数据时重新定位文件偏移，但不迫使内容相同的页面重新加载；轮次内容变化返回 409，前端重新打开当前版本。详情版本失效时明确要求重新打开会话，不把新结果塞入旧卡片。

这些缓存都是可丢弃的读优化。完整原文仍在原 JSONL，导出、账号归属和恢复逻辑保持原入口。
