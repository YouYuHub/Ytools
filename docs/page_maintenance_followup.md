# 任务状态与模块拆分

实施日期：2026-10-23。

## 页面行为

输入框上方增加一行任务状态。无当前任务记录时隐藏；状态不重复插入聊天正文。默认行高 24px，长说明省略，悬停可读全文；兼容明暗主题和窄屏，使用 `aria-live="polite"`，同一阶段的后续 token 不重复播报。

| 场景 | 显示与操作 |
|---|---|
| 正常生成 | 正在连接 → 等待模型 → 正在思考 / 生成回答 / 执行工具；并行工具显示未完成数量 |
| 暂停 | 区分等待操作确认、等待调整预算、等待你的回复；提示现有处理入口 |
| 重试与压缩 | 独立显示正在重试、压缩上下文；工具失败本身不等于主任务失败 |
| 任务收尾 | 区分已完成、已停止、任务出错和任务挂起；停止失败保留监听并允许重试 |
| 连接中断 | 显示连接已中断与“重新连接”；中断本身不能证明后台任务结束 |

重连先查询 `/chat_stream/status`：仍运行时以 `messages=[]` 附接并回放；已结束时重新读取历史。不会重新发送原提问。状态未确认前阻止新发送和自动派发队列，避免重复任务。切换会话仅断开本地监听；状态按会话隔离，旧请求的收尾、停止回执不能覆盖新任务。

本次复用已有 SSE、运行状态和待审批查询，不新增轮询。刷新页面后，运行中任务通过附接恢复阶段；已结束的旧任务以历史内容为准，不推断成功状态。手动压缩仍使用原有专用进度与停止流程。

后续侧边栏运行标记独立增加了批量状态同步，主任务状态栏本身仍不轮询；实施与等待/断线规则见 [会话运行标记](session_activity.md)。

## 模块职责

| 文件 | 职责 |
|---|---|
| `H5/js/task_state.js` | 无 DOM、无计时器的纯状态机；执行阶段与连接状态分别记录 |
| `H5/js/app/task_status.js` | 当前会话状态栏、有限会话缓存、重连操作及请求身份校验 |
| `H5/js/app/stream_pipeline.js` | 思考、正文、工具、压缩、回放和用量的流式渲染；发送与附接共用 |
| `H5/js/app/chat.js` | 发送、附件上传、停止、附接和标题触发；通过薄包装向渲染管线传入服务 |
| `factory/agent_runtime/builtin_tool_catalog.py` | 工具名称、选择常量及 14 份静态 Schema；仅依赖标准库 `copy` |
| `factory/agent_runtime/builtin_tools.py` | 工具注入与执行；显式重导出 catalog 常量以兼容原有导入路径 |

`read_media` 的定义按配置动态构造，仍保留在执行模块。静态 Schema 的字段与文字、工具选择规则、参数校验入口保持一致。

### 后续拆分约定

每次只抽取职责明确的部分，先固定行为，再搬移实现；原入口暂作兼容包装。不得在同一次搬移中顺带改变工具参数、历史格式或持久化事务边界。需要变更行为时单独增加用例。

后续优先评估 `messages.js` 的历史记录渲染器、`chat_factory.py` 的协议循环与工具批次派发。它们涉及历史窗口、进程通信与事务顺序，应分别实施；本次没有整体搬移这些模块。

## 验证

1. 拆分前记录前端及相关后端基线；拆分后重复执行，并逐字段比较 14 份 Schema。
2. 状态专项覆盖 EOF 与 `[DONE]`、并行工具、审批去重、预算、用户提问、重试、压缩、挂起、停止失败、跨会话及迟到回执。
3. 使用实际附接函数验证断流不派发队列、附接不重发提问；静态资源测试约束脚本依赖顺序与内容哈希。
4. 浏览器使用实际 CSS 和状态模块的隔离页面，检查明暗主题、窄屏、省略说明与重连按钮。它模拟状态，不调用真实模型或访问会话历史。
5. 完整前端通过 `live_tail_fixture.cjs` 使用模拟 API 执行真实发送、渲染与滚动流程，核对生成阶段和正常收尾状态。

浏览器验证页可在项目根目录执行 `node H5/test_browser/maintenance_fixture.cjs`，打开输出的本机地址；结束后 Ctrl+C。

单元回归：`npm test --prefix H5`；后端回归与资源构建见 [维护说明](project_maintenance.md)。本次最终验证数量见下方实施记录，后续以实际测试为准。
