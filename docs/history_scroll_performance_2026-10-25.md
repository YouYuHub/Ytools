# 长会话滚动与折叠性能修复（2026-10-25）

## 问题与处理

录屏对应历史包含 769 条记录。折叠后，一个摘要可能代表上百条思考、工具及结果记录；原来按固定记录数切换窗口，会切入同一个折叠段，实际挂载的可见内容不足一屏。滚动继续触发窗口重建，随后估算高度与实际高度的补偿使内容跳变、出现空白。

本次调整：

- 普通滚动按可视高度规划前后缓冲窗口；关闭的连续过程作为完整边界，展开后的过程仍可分窗口加载。
- 换窗保留当前阅读节点的位置；更新占位高度后重新读取锚点坐标，避免用旧布局计算补偿。中途折叠时摘要统一映射到整个过程的起点，展开选择变化时同步重算高度索引。
- 摘要使用完整过程的思考/工具/子任务计数，避免只统计当前分片；依赖结果不跨轮扩展上一轮的折叠段。
- 主会话历史工具的差异视图及代码高亮延迟到用户打开工具详情时生成，标题统计和路径立即显示。清除或替换结果会一并清除延迟状态。历史思考完成回放后清理预览定时器。

主要实现：`H5/js/app/history_scroll.js`、`process_groups.js`、`messages.js`。资源哈希已更新。

## 分步验证

1. 从录屏对应会话生成脱敏布局夹具，保留记录种类、长度和标点布局，不在报告或测试日志中保存原始对话文字。初始解析约 7ms，主要问题集中在 DOM 换窗与布局。
2. 新增折叠边界、展开窗口和跨轮依赖的单元测试；验证历史差异默认不生成 DOM，首次打开生成、清除后不恢复旧内容。
3. 使用真实 Chromium、独立 HTTP 服务和临时账号运行滚动回归。96 次滚轮输入覆盖反复上下滚动，另测最长过程展开、中途分片折叠和滚动条释放。
4. 再用 30 轮、4170 条合成记录验证长历史；运行全部前端测试和跨页浏览器流程。

相同 769 条脱敏布局、1600×900 视口、相同滚轮序列的实测：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 历史窗口重建次数 | 108 | 9 |
| 窗口重建累计同步耗时 | 961.2ms | 279.5ms |
| 单次重建最大耗时 | 19.7ms | 74.8ms |
| 视口顶部最大空白 | 387px | 64px（正常顶部留白） |
| 同向滚动中的阅读位置反向次数 | 0 | 0 |

修复后首次尾段渲染约 41.4ms，最长过程点击展开处理约 9.2ms，中途折叠摘要偏移 0px。30 轮夹具首次尾段渲染约 15.8ms，展开处理约 3ms，滚动期间 26 次窗口重建、无阅读位置反转。

合并窗口降低了总重建次数和累计耗时，单次批量渲染可能更长；本次 769 条夹具中仍有两次超过 50ms。因此这些数字说明本机回归改善，不能承诺任意大消息或设备都达到每秒 60 帧。上述耗时为浏览器同步处理时间，不包含网络下载、完整会话解析或最终屏幕绘制时间。

滚动条测试在浏览器内驱动滚动坐标，经过应用真实的按下/释放处理，检查拖动期间 `scrollHeight` 不变、无大块空白、最终回到底部。无头 Chromium 不提供原生滑块移动接口，此项不等同于人工拖动验收。

最终结果：

- H5 全量：790 passed。
- 独立服务跨页浏览器：5 passed（编辑器、验证器管理、切换账号、断线刷新、长会话滚动）。
- 录屏会话脱敏布局浏览器专项：1 passed。
- 资源哈希校验：4 passed；修改的 JavaScript 语法检查通过。
- 本机服务 `127.0.0.1:48621` 的三个修改脚本均返回 HTTP 200，响应内容指纹与磁盘最新文件一致。
