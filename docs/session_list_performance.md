# 会话列表首屏优化

侧栏通过 `GET /chat_history/summaries` 一次取得全部轻量摘要；旧的 `/chat_history/sessions` 文件名列表接口保留兼容。摘要仅包含 `id`、`filename`、`title`、`updated_at`、`created_at`、`group_id`。

摘要读取在后台线程执行，不创建 `ChatMemoryManager`，不解析完整历史、不重算 usage、不查询权限库、不改写 JSONL。先单次查询会话登记表与归档快照，在内存中过滤删除状态与归档范围，再逐个只读首行（最多 2 MiB），不再逐会话查库。空问题列表是正常状态；首行损坏、过大、文件暂时不可读时，使用会话标识与文件修改时间兜底，真实内容仍在打开会话时按原有路径读取/恢复。符号链接和非普通文件不参与列表。

传 `?session_id=xxx` 可单独查询目标会话是否存在，结果仍为数组，不存在返回 `[]`，不会创建空会话。前端启动时并行请求侧栏列表和目标摘要，目标存在即可打开，不等待所有侧栏节点完成；用户先切会话、新建、发送/上传或编辑输入时，迟到的启动结果不会抢走当前视图。

普通侧栏每批渲染 50 行，批间让出主线程，首批立即显示；排序使用原有后端更新时间与本地最近交互合并规则。完整数据立即提供给分组和多选；切换多选/重新加载会取消旧的渲染批次。请求序号防止慢的旧列表覆盖新列表，刷新失败保留原列表。旧后端没有摘要接口时，退回文件名列表与本地标题，不恢复逐会话元数据请求。

服务启动后独立后台线程只检查 `.pending` 检查点：写者存活、权限系统保存了可恢复任务、对应历史不存在或收到停止信号时跳过。孤立检查点继续使用已有跨进程锁、轮次去重和中断恢复逻辑；不会自动执行工具，也不会绕过权限确认。正常会话不因列表加载而初始化管理器。打开具体会话时的恢复路径继续保留。

首版不新增 SQLite 缓存。列表每次仍扫描目录并读取各首行，适合数百个会话；更大规模时可以再增加可重建的摘要索引。这里的后台线程仅处理启动恢复，不是周期轮询。
