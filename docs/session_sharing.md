# 会话分享与权限迁移

2026-10-15：分享包升级为 manifest v3。持久化会话统一下载 ZIP，单会话没有附件时也携带权限快照；旧版 ZIP、裸 ZIP 和 JSONL 仍可加载。

## 包内数据

```text
manifest.json
<session>_chat.jsonl
session_files/<upload_id>/...
state/permission_runtime.sqlite3
```

权限文件是一份新建的独立 SQLite 快照，包含 `share_metadata(format, version)` 和 `policies(scope, mode)`，每个导出的会话对应一条 `session:<id>` 记录。`mode` 为 `ask`、`full_control` 或 `NULL`（跟随全局）。它只读取本地已提交的会话配置，能包含尚在 WAL 中的已提交数据，**不是整个运行数据库的文件复制**。

以下内容不随包：全局权限、未选择会话、任务与恢复请求、审批和批准记录、执行台账、数据库备份、搜索缓存、Messages/Responses 私有侧车。聊天数据中的原生协议引用、远端链状态、审批控制事件与模型自定义请求头也会去除；正文、思考、工具参数和已记录结果、模型选择与常规参数、本地压缩摘要继续保留。

工具参数和结果本身属于会话内容，仍会随分享保留；分享前应核对其中是否包含不希望提供给接收方的业务数据。

## 加载行为

预检弹窗显示每个会话的权限。用户确认加载后，后端只合并成功导入会话的配置，随后前端重新读取该会话的有效权限。

| 选择或包格式 | 权限处理 |
|---|---|
| 新会话 | 会话配置写入本地 `policies` |
| 重命名另存 | 配置映射到最终新 ID；同名本地原会话保持原配置 |
| 覆盖 | 只更新被覆盖会话；如果包内为 `NULL`，清除该会话覆盖，跟随接收端全局 |
| 跳过 | 不修改该会话的内容和权限 |
| 无权限快照的旧 ZIP / 裸 ZIP / JSONL | 不修改本地权限；已有覆盖保留，新会话跟随本地全局 |

接收端全局权限、其他会话的配置和待处理任务始终保留。发送端若设置全局完全控制、某会话选择跟随全局，接收后仍是「跟随全局」，不将发送端的全局完全控制固化为会话覆盖。导入配置后开启的新任务使用接收端数据库中的有效模式；发送端尚未完成的任务不会跨机器自动恢复。

## 校验与失败处理

- 先在隔离临时目录以只读方式校验权限快照，检查格式、版本、表结构、模式和会话清单；快照限制为 2 MiB。声明存在却缺失或损坏时拒绝整个包，不静默丢弃配置。临时文件不会复制到本地状态目录。
- ZIP 的压缩后和展开后数据均受 512 MiB 上限约束，会话最多 100 个；拒绝重复路径、路径穿越、Windows 盘符/ADS 路径、加密文件和符号链接。
- 本地目标仍有生成中或挂起任务时，拒绝覆盖；可另存，也可先停止/放弃本地任务再覆盖。
- 配置按单会话事务合并。权限写入失败时还原该会话原 JSONL（新建目标则移除），不会用空库覆盖现有数据库；原生 Responses 链可能已被标记为需重建，下次按本地历史初始化。
- 附件先写新目录，成功后才发布历史与配置；写入失败不清空原附件。覆盖成功后仅清理已无会话引用的原目录。上传目录名不等于会话 ID 时，按 manifest 的 `upload_id` 读取并在导入后改写归属，避免重复分享丢附件。
- 单会话导入失败进入 `failed[]`，其他可导入会话继续处理；有效配置、跳过项与原有本地状态不会因其他项失败而被清空。

本机完整备份仍应备份整个 `history_files`，权限快照分享用于转移会话配置，不能替代包含审批和恢复台账的完整数据库备份。
