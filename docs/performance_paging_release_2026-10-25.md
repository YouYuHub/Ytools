# 存储计量、历史分页与发布验收改进

## 1. 准确容量统计

`security/storage_usage.py` 用一次 `os.scandir` 元数据遍历替换逐文件 `Path.resolve/is_file/stat`，重叠目录只计一次，不读取正文，不跟随符号链接或 Windows 目录联接；文件中途消失可容忍，权限错误不会按零容量忽略。

仍在每次准入时准确统计，不跨请求缓存总量。后台检查点、协议日志和可信主机工具可绕过大文件写入锁改变文件，因此直接缓存容量会漏算；这一实现保留现有配额与写锁规则，不需要新的持久化账本或数据库迁移。复杂度仍与账号文件数量有关。

现有 `API latency` 记录补充 `storage_scan_ms`、`storage_files`、`model_slot_wait_ms`，便于区分磁盘计量与模型并发排队。无限额账号不执行容量扫描。

同机、临时数据、3 次中位数对照：

| 环境与规模 | 原流程 | 新流程 |
|---|---:|---:|
| Windows 1000 个文件 | 673.4 ms | 4.7 ms |
| Linux / WSL `/tmp` 10000 个文件 | 208.1 ms | 29.8 ms |

Windows 10000 文件新流程约 50.4 ms。基准检查统计字节完全一致，只测元数据遍历，不代表整体模型首帧速度或其他硬件结果。复验：`python scripts/benchmark_storage_usage.py --files 1000 --reference`。

初步验证：Windows、Linux 相关计量／存储／额度／发送计时回归各 45 项通过。

## 完整门禁发现并处理的回归

- 旧 Messages 测试夹具只替换了私有 `_root()`，与账号存储的路径选择不一致。夹具改为使用真实受管目录再重定向到临时目录，校验原生回放和单会话删除；未放宽生产递归删除保护。Windows、Linux 相关 109 项均通过。
- Windows 真实 stdin／EOF 组合测试发现：输入已经执行，但并发读取短暂占用 ACK 文件，原子替换报 WinError 5，回执停在 `writing`。命令元数据提交改为有界重试，监督器允许回执线程完成重试；只重试文件提交，不重发输入。新增确定性故障注入验证输入只送一次、最终回执正确、无临时正文残留。最终 Windows 终端组合 61 项、Linux 53 项通过；独立启动的真实 CMD 输入／EOF 连续 15 次全部通过。
- 实际上滚补测发现原有虚拟滚动样式会隐藏服务端页间入口。已将新入口与本地 DOM 分片提示区分，保留可见点击区域；浏览器验证交叉页自动加载和阅读锚点。

源码或资源在验收途中改变的报告不会用于发布。最终以冻结版本的完整通过报告为准。
