# 压缩完成后仍转圈：前端生命周期修复

实施日期：2026-10-23。

## 原因

本次核对的会话落盘记录有成对的手动压缩 `start/done`，没有证据表明后台重复调用压缩模型。前端完成事件只更新当前卡片，仍连接时不会清理历史回放或重连产生的运行副本；过程分组据这些副本继续显示转圈。刷新重读完整历史后，配对渲染恢复正常。

另外，实时尾部缓存会补回仅从 DOM 移除的卡片，以及历史窗口重建前的旧分组标题；重连若在旧请求 `finally` 之前启动，旧请求还会清掉新请求的运行标志与取消器。

## 当前规则

- 同一运行阶段复用卡片，附接可接管历史运行卡；完成/中止时清理重复运行副本，同步未闭合的内存历史记录。已完成批次和独立摘要合并记录保留。
- 实时缓存只保存内容节点，过程标题由分组模块重建；永久移除的副本不再被窗口恢复。完成摘要及压缩前预览在窗口重建后仍可查看。
- 连接提前 EOF 不当作成功。自动附接最多一次，等旧请求清理后再启动；附接 404 明确结束状态，压缩重连使用压缩接口。
- 业务最终结果之后的迟到事件、读取器断线不覆盖终态；缺少阶段终态时停止显示该卡片的运行动画，并说明结果待核实，保留部分输出。
- 连接状态未知时保留“连接已中断”提示，不宣称后台已停止，不自动派发队列；显式停止失败保留监听，旧停止回执不能取消新请求。

只调整前端状态与显示，不改压缩模型、预算、摘要算法或历史文件。更新资源后刷新页面即可，无须为本次修复重启后端。
