# 视频准备阶段停止后的轮次一致性

2026-10-20 修复：带视频的消息在首字响应前停止，切换模型后编辑重发提示“轮次号 35 超出范围，当前共 34 轮”。

视频引用解析原先同步阻塞 worker 事件循环。停止超时强制退出后，最新提问可能只保存在 `.pending` 中；主进程已缓存的历史管理器不会再次执行构造时的恢复逻辑，删除预演只数已落盘轮次，因而与前端已收到的编号不一致。

现在提问及原始媒体引用先保存检查点，再推送 `round_started`，然后执行历史压缩、视频解析和模型调用。视频解析移入工作线程，停止命令能在解析期间被处理；只有媒体而没有文字的提问也会保存。

停止接口确认 worker 结束当前生成后，会在返回前把尚未提交的检查点收尾。编辑重发和插入位置同时写入检查点，停止恢复或进程重启时仍按原位置写回，保留其他轮次与有效摘要。写入历史成功后才清理检查点；重复恢复不会追加重复轮次。仍在工作的写者不会被启动恢复流程改写。

前置压缩或预算检查失败时，已经接受的提问也会收尾，不残留永久 `running` 检查点。worker 已收到但尚未确认启动的生成请求同样算运行中，避免用户在冷启动期间点击停止被提前返回成功。

回归覆盖三种 API 的视频/纯视频输入、准备阶段停止后切换模型重发、主进程缓存与重启恢复、原地编辑与插入位置、删除预演、写入失败保留检查点，以及真实 Responses HTTP 计量。

停止不会撤回已经发给服务商的请求。被取消的视频解析线程可能短暂继续本地处理，但不会再进入该任务的模型调用。
