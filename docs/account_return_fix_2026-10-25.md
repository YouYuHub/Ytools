# 从账号页返回聊天时的初始会话加载失败

## 原因

聊天入口将没有 `session` 参数的 `/ui/` 当作 `default` 会话打开。身份客户端又为带会话 ID 的请求先执行注册，包括原本只读的会话摘要查询。存在未迁移或其他账号的旧 `default` 时，注册会被权限校验拒绝，继而显示“初始会话暂时无法加载”。侧栏列表不带这个 ID，因此仍可正常显示。

此外，账号入口和“返回聊天”原来没有携带当前会话，导致返回后进入上述默认分支。

## 调整

- 无明确会话 ID 时正常进入新对话，保留显式 `?session=...` 深链接。
- 只读会话摘要查询直接查询，不预先创建会话归属。新会话实际操作原有的注册和权限检查保持有效。
- 设置菜单进入账号页时携带当前会话，账号页返回链接使用固定的本机聊天路径并编码 ID；参数不能变成外站跳转。
- 离开聊天页时同步当前浏览器历史项，使浏览器“后退”在页面重新加载时也能恢复当前会话；新对话会清除旧会话参数。
- 初始加载的过期响应、用户切换和正在输入的保护逻辑保留；真实网络错误仍显示加载失败提示。

主要修改：`H5/js/app.js`、`app/sessions.js`、`app/session_archives.js`、`security_client.js`、`account.js` 和 `H5/account.html`。资源哈希已刷新，无后端实现或账号库变更。

## 验证

使用独立 HTTP 服务、临时账号和不属于任何账号的旧 `default` 历史复现。修复前，首次打开及账号页返回分别尝试注册 `default`，浏览器用例失败；修复后不再发起这些注册请求。
