# 设备丢失后的账号恢复

## 哪种情况还能登录

| 手头可用的信息 | 处理方式 |
| --- | --- |
| 密码＋另一台已绑定的验证器 | 正常登录，在验证器管理中移除丢失设备，或更换全部验证器。 |
| 密码＋一条未使用恢复码 | 登录页展开“设备丢失／无法使用验证器？”。可用恢复码登录；设备丢失时建议直接点击“用恢复码更换丢失设备”，扫码确认后停用全部旧设备。 |
| 知道密码，但所有验证器和恢复码均丢失 | 服务器管理员核验身份后，在服务器项目目录执行 `reset-mfa`。随后用原密码登录、重新扫码并保存新恢复码。 |
| 密码也忘记 | 由服务器管理员先执行 `reset-password`；若 MFA 也不可用，再执行 `reset-mfa`。 |
| 没有任何恢复信息，也无法联系服务器管理员或取得服务器管理权限 | 无法安全恢复；网页不提供绕过 MFA 的后门。先恢复服务器管理权限，再按上面的流程操作。 |

本项目没有配置并验证过的邮件恢复渠道，因此不会仅凭用户名、普通邮件地址或已登录浏览器自动解除 MFA。上述说明针对 Ytools；GitHub 等第三方账号使用各自的恢复机制。

## 使用恢复码

在登录页先输入账号密码，再展开设备丢失指引。恢复码和动态码使用同一验证接口，每条只能使用一次。支持粘贴前后空格、大小写及分组连字符，不会使已使用的码重新生效。

选择“用恢复码更换丢失设备”后：填写一条未使用恢复码，生成二维码，用新手机 Google Authenticator 或 Microsoft Authenticator 扫码，再输入新条目的六位动态码确认。确认前旧设备仍有效；确认成功后全部旧验证器、旧恢复码及其他登录失效。请保存本次生成的新恢复码。

只重新生成恢复码不会停用丢失设备上的验证器，需要同时使用更换或移除设备操作。

## 没有恢复码：服务器本机恢复

由可信服务器管理员核实账号本人身份后，在项目目录执行。使用与运行服务相同的 Python、OS 账号和环境配置，尤其是 `YTOOLS_SECURITY_DIR`；远程部署需通过 SSH 或服务器管理控制台，网页用户不能直接执行。

Windows 本机：

```powershell
C:\Python314\python.exe scripts/manage_accounts.py reset-mfa --username admin
```

Linux（示例使用项目虚拟环境，请替换为服务实际解释器）：

```bash
./.venv/bin/python scripts/manage_accounts.py reset-mfa --username admin
```

将 `admin` 换成待恢复用户名。命令立即撤销该账号全部登录、旧验证器、恢复码和未完成绑定，保留密码、角色、账号 ID 与数据归属。所有角色，包括普通成员，下一次都必须重新扫码确认才能进入工作区；这不受原来的可选 MFA 设置影响。已有其他用户不受影响。此命令读取在线数据库，无须为了账号恢复本身重启服务。

若密码也遗失，先运行相同解释器下的：

```text
python scripts/manage_accounts.py reset-password --username admin
```

将 `python` 换成上述服务实际解释器。终端会隐藏输入并要求两次确认新密码；不要将密码放在命令行参数或聊天中。需要时再运行 `reset-mfa`，之后重新登录绑定。不要删除账号数据库、`mfa.key` 或重新创建账号，这些操作可能损坏既有账号和数据访问。

## 预防下次丢失

首次绑定和更换后的恢复码区域都提供“下载恢复码”。文件由浏览器在本机生成，仅在本人点击后下载；请存到与手机独立的密码管理器或安全备份位置。

已有账号可打开 **设置 → 账号与安全 → 验证器管理 → 恢复码备份**，查看剩余数量。旧码丢失时，填写上方当前密码和有效动态码／恢复码，点击“重新生成恢复码”并确认。新码仅显示一次，旧恢复码和其他登录立即失效，原有验证器保持有效。清除显示或离开页面后不再保留原文，可再次验证身份重新生成。

## 实现边界

账号库版本 4 在版本 3 基础上仅增加恢复后必须重新绑定的标记表。升级不会为现有用户设置此标记，也不改变其密码或原验证器。只有服务器本机授权恢复操作才写入标记；成功绑定新验证器后原子清除。

恢复码仅保存摘要，不能查看旧码原文。重新生成要求完整登录、密码及当前因子，保留 Origin、CSRF、频率限制、动态码防重放和安全审计；没有新增匿名重置接口。
