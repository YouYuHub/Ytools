# 长会话最新消息显示修复（2026-10-23）

## 原因和处理

- 主页面使用历史窗口和实时尾部节点，问题导航另有完整索引，因此导航能显示新问题不代表底部布局正确。
- 滚动重建历史窗口时，当前流先被挂回；若随后只追加缺失的旧轮节点，旧回答会排到最新回答后面。现在按保存的顺序恢复完整实时尾部。
- 后加入的回放提问、过程摘要按相邻节点记入顺序，保持提问在回答之前、摘要在其过程之前。
- 恢复节点时同时清理过期的 `history-live-hidden`；即使已在末尾历史窗口，“回到底部”也会修复可见性。
- 浏览旧历史时继续接收流式内容并保留阅读位置；返回末尾后恢复显示。正常流式跟随不重复重建问题导航。

## 后续修复：滚动位置与问题导航同步（2026-10-23）

长回答或密集工具过程可占满历史窗口，所属提问已被卸载。旧导航只检查用户气泡的屏幕位置，找不到气泡时回落到第一条；窗口重建期间的临时布局也可能残留为最终高亮。

- 根据可见历史记录的下标回查完整问题索引，提问不在 DOM 中仍可定位；忽略隐藏、零高度与已卸载节点。
- 完整会话到底时按完整索引选中最后一条；回退分页窗口的局部底部不视为会话结束。
- 历史布局刷新、窗口替换及原生拖动释放完成后同步导航，复用原有刷新帧，不重建整个问题列表。

新增 `qnav_scroll_sync.test.js`，并扩充 `history_live_tail.test.js`，覆盖无提问气泡、中段长回答、折叠记录、过期 DOM、零高度时间戳、超过 40 条的采样轨道和拖动收尾顺序。

独立浏览器场景：`node H5/test_browser/qnav_scroll_fixture.cjs`。真实前端加载 600 条模拟记录、3 个问题，可用原生滚动条、滚轮或页内按钮检查顶部/中段/底部；不调用模型或访问真实历史。验证了双向滚动与拖动，窗口内提问数为 0 时仍能高亮第 2/3 个问题。

本轮前端全量 690 项、资源版本检查 1 项通过；浏览器未发现控制台错误。刷新前端即可生效，无需重启后端。

## 后续修复：接近底部时重复回跳（2026-10-24）

录屏会话的末尾含长回答、Mermaid 和轮次用量。距离底部十几像素时，窗口覆盖判断只计底部 padding，漏计末尾占位 gap 和外边距，将正常留白误判成历史未加载。重建窗口后图表先折回占位高度，滚动按估高定位到回答中段；继续下滚又触发重建，表现为最后一段反复出现。

- 覆盖范围计入首尾 padding、外边距和尾部 gap；已经完整显示的末尾不重复创建 Markdown/图表。
- 原生底部采用 2px 容差，与吸底判断一致，兼容设备缩放后的小数 scrollTop。
- 留白补偿只在完整会话首尾生效，中间窗口仍正常加载未显示的历史；保留用户向上浏览与原生滑块拖动行为。

验证：新增 4 项回归；前端全量 759 项、资源版本检查 1 项通过。浏览器使用录屏会话的记录结构和最后回答，替换之前的消息及工具参数/回执为模拟文本，不修改实际会话。在 2450×1142 录屏尺寸下，修复前距底 12px 会重建并向上回跳约 1900px；修复后同场景及连续下滚均为 0 次重建、0 次回跳。

复现入口：`node H5/test_browser/history_bottom_fixture.cjs`；可选首个参数为本地历史文件，只读提取结构与最后一条回答，其余内容使用模拟文本。此入口只在 127.0.0.1 提供隔离页面，不调用模型；支持长图表、纯文本和单条长回复对照。阶段日志见 `tmp/history-bottom-before.log`、`tmp/history-bottom-focused.log`、`tmp/history-bottom-h5.log`。更新前端后刷新页面即可，无需重启后端。
