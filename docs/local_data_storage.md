# 本地数据存储

## 目录与职责

| 路径 | 内容 | 性质 |
|---|---|---|
| `history_files/*_chat.jsonl` | 聊天历史与会话元数据 | 持久数据 |
| `history_files/session_files/<session>/` | 上传文件、媒体、解析记录和文件修改记录 | 会话数据 |
| `history_files/state/permission_runtime.sqlite3` | 权限选项、审批、任务恢复和工具执行台账 | 持久控制数据 |
| `history_files/state/task_costs.sqlite3` | 任务预算、模型价格、完整用量和预算等待状态 | 持久计量数据；见[任务预算](task_budgets.md) |
| `history_files/state/backups/permission_runtime.legacy-*.sqlite3` | 从旧路径迁移时生成的完整权限库快照 | 迁移备份 |
| `history_files/sidecars/history_search.sqlite3` | 从聊天 JSONL 提取的搜索文本和位置 | 可重建缓存 |
| `history_files/sidecars/` 中其他文件 | 待落盘轮次、摘要/协议相关记录、历史备份等 | 应按具体文件用途保留，不能把整个目录视作缓存删除 |
| `history_files/lock/` | 跨进程写锁与迁移锁 | 协调文件，进程退出后系统释放锁 |

## 权限数据库

权限选项继续使用 SQLite。配置本身体积很小，性能差异不是决定因素；将全局与会话选项、审批及恢复数据放在一个控制存储中，可以统一使用事务和并发写入控制，不需要修改 `.env` 或重写聊天 JSONL。

| 表 | 保存内容 |
|---|---|
| `policies` | 全局模式、按会话设置的覆盖模式；没有会话覆盖时跟随全局，首次默认为询问 |
| `tasks` | 任务状态、会话、所属进程、恢复代次、工作目录与权限快照；活动任务保留恢复请求 |
| `checkpoints` | 主/子任务恢复位置、消息上下文、进行中轮次、模型与工具配置指纹 |
| `approvals` | 调用 ID、待确认/允许/拒绝/完成状态、冻结参数、实际路径、服务指纹和计划摘要 |
| `executions` | 每次工具调用的执行状态、完成结果；用于恢复和避免重复执行 |

任务结束后删除检查点、原请求和工具结果正文；保留轻量任务/审批/执行记录。删除会话会清理它的权限覆盖及任务记录，全局配置继续保留。

分享包 manifest v3 在 `state/permission_runtime.sqlite3` 中携带**仅所选会话配置**的独立 SQLite 快照，含 `policies` 与 `share_metadata` 两张表，不复制正在使用的数据库文件。全局策略、其他会话、任务、审批、检查点、执行台账和备份不随包。读取通过 SQLite 查询获得已提交数据，包含 WAL 中的配置，不需要停止后端。

加载分享包时先在临时目录只读校验快照，再把成功导入会话对应的配置写入本地 `policies`：另存时映射到新会话 ID；覆盖只更新目标会话；跳过不写入；`NULL` 表示跟随接收端全局配置。始终保留接收端全局策略及其他会话的配置和任务，不把包内 SQLite 覆盖到本地路径。旧版 ZIP 与单独 JSONL 没有此快照时保留已有目标会话权限，新会话跟随本地全局。详见 [会话分享与权限迁移](session_sharing.md)。

SQLite 不会因为删除数据立刻缩小主文件，空闲页会被后续写入复用。本次迁移在离线快照上整理空闲页，不删除业务记录。

## 搜索数据库与体积

这份库与权限库完全独立：

- `settings` 保存索引版本和查询快照版本。
- `sessions` 保存文件名、会话 ID、标题、更新时间、文件指纹和坏行计数。
- `documents` 保存抽取的可搜索文字、原始轮次/事件位置、角色、字段、时间及子任务 ID。这里的 document 指文本单元，不是上传文档原件。

搜索覆盖用户问题、助手回答与思考、工具参数/结果、子任务文字、压缩摘要、引用、标题和文件名。每段内容保存原文 `text` 与 Unicode 大小写规范化后的 `search_text`，便于字面匹配和返回原文片段，因此文本数据大致保存两份，还存在表和索引的开销。

2026-10-15 检查当前工作区时，搜索缓存约297 MiB，含129个会话、74,265条文本单元；其中原文约133 MiB，规范化文字约133 MiB。权限库迁移前约252 KiB，整理空闲页后约60 KiB；3条策略、7个任务、9项审批、14条执行记录全部保留，检查点为0。两份数据库没有共用表；这些统计会随使用变化。

搜索缓存可以在停止搜索/后端后删除，下次搜索按 JSONL 重建；权限数据库丢失会失去配置、待审批和恢复数据，不能当作缓存清理。日常无需为了大小反复删除搜索缓存。

## 从旧权限库迁移

1. 停止旧后端后使用新版本；不要让新旧版本同时使用同一数据目录。
2. 新路径尚不存在时，自动读取旧 `sidecars/permission_runtime.sqlite3`，通过 SQLite backup API 合并已提交 WAL 数据形成完整快照。
3. 整理快照空闲页并检查完整性，保存迁移备份，再原子放置到新路径。随后清理旧主文件与其日志；旧文件被占用时保留并在日志说明。
4. 快照/写盘失败会保留旧文件并报错；已经存在的新库不会被旧库覆盖。后续读写统一使用新路径。

备份整个 `state/` 时建议先停止后端，或者使用 SQLite backup API 获取一致快照；运行中的数据库可能还有 `-wal` 中尚未合并的数据。迁移备份已经是独立单文件，可以直接留存。停止后端且确认不再需要回退时，可以自行删除迁移备份；不要删除正在使用的主数据库。
